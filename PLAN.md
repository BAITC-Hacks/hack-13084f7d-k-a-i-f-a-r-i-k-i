# Пошаговый план реализации OrgDiff Agent

Это рабочий список выполнения. Спецификация моделей и алгоритмов — в
[AGENTS.md](AGENTS.md), схема системы — в [docs/architecture.md](docs/architecture.md).
После выполнения каждого пункта его статус меняется на **[Done]** только при

**[Todo]**, текущая работа — **[In progress]**. Следующие сессии продолжают с
первого незакрытого этапа и обновляют этот файл.

демо, загрузка документов, eval, чат и отчёт проверены. Инструкция: [docs/docker.md](docs/docker.md).

## Правила закрытия этапов

- После изменения кода запускать соответствующие тесты и общий `pytest -q`,
  проверять `ruff check .` и `ruff format --check .`.
- Контейнерные зависимости расширять по мере появления импортов новых этапов;
  полный runtime должен содержать `pipeline`, `ui` и OCR.
- LLM-тесты запускать явно с `--run-llm`; mock-проверки не заменяют acceptance,
  для которого спецификация требует реальный API.
- Отметка [Done] означает реализацию и проверку, а не наличие файла-заглушки.
- Каждый этап вести в отдельной ветке. До настройки Git remote изменения
  фиксируются локально; удалённый PR не считается созданным.
- Не включать эталонные ответы в production-алгоритмы. Исходный и тестовый
  комплект могут переименовываться только по явному запросу пользователя;
  содержимое документов при восстановлении имён сохраняется.
